# 05. Data Models - Relational, Document, and Graph

#### Relational Data Model

**Definition:** The relational model was proposed by Edgar F. Codd in 1970 and is based on set theory and predicate logic. Data is represented in tables (relations), where each table consists of rows (tuples) and columns (attributes).

##### Characteristics

- **Table Structure:** Data is stored in tables with clearly defined rows and columns.
- **Referential Integrity:** Ensures data consistency through primary keys and foreign keys.
- **Normalization:** The process of organizing data to reduce redundancy and improve data integrity.
- **SQL:** The standard language for querying and manipulating data in relational databases.

#### Document Data Model

**Definition:** In this model, data is stored in documents, typically in formats such as JSON or XML. Each document can have a different structure, providing flexibility in data representation.

##### Characteristics

- **Flexibility:** Documents can have varying structures without requiring a fixed schema.
- **Performance:** Often optimized for fast reads and scenarios where the data structure may evolve over time.
- **Scalability:** Many document databases are designed to scale horizontally with ease.
- **Nesting:** Allows related information to be stored directly within a single document instead of separate tables.

**Examples of Databases:** MongoDB, CouchDB, RavenDB.

#### Graph Data Model

**Definition:** The graph model represents data as nodes (entities) and edges (relationships). It is particularly useful for scenarios where relationships between data are just as important as the data itself.

##### Characteristics

- **Nodes:** Represent entities in the graph.
- **Edges:** Represent relationships between nodes.
- **Properties:** Both nodes and edges can have associated properties.
- **Relationship Queries:** Graph databases are optimized for queries that involve traversing and analyzing relationships, such as finding the shortest path between two nodes.
- **Flexibility:** Naturally represents complex and highly interconnected data.

**Examples of Databases:** Neo4j, OrientDB, ArangoDB.

Each data model has its own strengths and is suitable for different types of applications and requirements. For example, relational databases are often preferred for applications that require strong data integrity and consistency, while document databases are better suited for applications that require schema flexibility. Graph databases, in turn, are ideal for applications that need to analyze and work extensively with relationships between data.
