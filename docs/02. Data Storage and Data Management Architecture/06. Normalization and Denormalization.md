# 06. Normalization and Denormalization

#### Normalization

Normalization is a systematic process used to organize data in a relational database to reduce redundancy and improve data integrity. The goal is to ensure that each piece of information is stored in only one place. Normalization is achieved by dividing larger tables into smaller ones and using foreign keys to establish relationships between them. Normalization is measured using normal forms (NFs), the most common of which are:

**First Normal Form (1NF):** A table is in First Normal Form when it has a unique primary key and every column contains atomic (indivisible) values.

**Second Normal Form (2NF):** A table is in Second Normal Form when it is already in 1NF and all non-key attributes are fully functionally dependent on the entire primary key.

**Third Normal Form (3NF):** A table is in Third Normal Form when it is already in 2NF and all non-key attributes are mutually independent and directly dependent on the primary key.

There are additional normal forms (BCNF, 4NF, and 5NF), but normalization typically involves bringing data up to Third Normal Form (3NF).

#### Denormalization

Denormalization is the process of intentionally introducing redundancy into a database. It is essentially the opposite of normalization. Denormalization is performed to improve performance in scenarios where read operations are more critical than write operations. By doing so, it reduces the need to join multiple tables, which can be expensive in terms of performance.

##### When to Use Each One

##### Normalization

- When data integrity is critical, such as in transactional databases.
- When minimizing data redundancy and preventing insertion, update, and deletion anomalies is required.
- In transaction processing systems (such as OLTP systems), where write operations are frequent and data integrity is essential.

##### Denormalization

- When read performance is more important than absolute data integrity.
- In analytical systems (such as OLAP systems), where queries are complex and read operations occur more frequently than write operations.
- When join operations become a performance bottleneck.

Normalization aims to minimize redundancy and maintain data integrity by decomposing tables into smaller, related structures. Denormalization, on the other hand, aims to improve performance, often at the cost of introducing some redundancy. The choice between normalization and denormalization depends on the specific requirements of the system and its performance goals.
